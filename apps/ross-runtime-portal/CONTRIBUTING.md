# Contributing

## Engineering workflow

1. Create a focused issue or change record.
2. Branch from the approved base.
3. Keep changes scoped and reversible.
4. Add or update tests, API contracts, schemas, migration notes, and documentation.
5. Run formatting, linting, tests, policy validation, dependency checks, and security checks.
6. Open a pull request documenting risk, validation, deployment, and rollback.
7. Obtain required reviewers before merge.

## Required evidence

- problem statement and intended outcome;
- files and modules affected;
- security, privacy, availability, and compliance impact;
- test results;
- deployment and rollback instructions;
- screenshots for interface changes;
- confirmation that no secrets or personal data are included.

Never commit taxpayer records, SSNs, account numbers, tokens, private keys, identity-document images, or production logs containing personal information.
