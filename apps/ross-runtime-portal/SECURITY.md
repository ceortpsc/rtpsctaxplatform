# Security Policy

## Private reporting

Do not open a public issue for suspected vulnerabilities involving authentication, authorization, secrets, personal data, injection, code execution, file upload, infrastructure access, or dependency compromise. Use the organization's designated private security channel.

Include the affected component and version, reproduction steps, impact, sanitized evidence, and suggested mitigation when available.

## Response lifecycle

Acknowledge, triage, contain, reproduce, remediate, validate, coordinate disclosure, and record lessons learned.

## Testing boundary

Testing must not access another person's data, persist unauthorized access, exfiltrate secrets, degrade availability, or target third-party systems without authorization.
