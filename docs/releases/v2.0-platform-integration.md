# RTPSC v2.0 platform release integration

The governed release registry introduced in `config/release-channels.json` is the single source of truth for Ross Tax Pro Software Co Enterprise Tax Platform v2.0 channels.

## Active repository identity

The registry default is:

```text
Channel: alpha
Public tag: v2.0-alpha
Package version: 2.0.0-alpha.0
Deployment environment: alpha
```

The root `package.json`, `./rtpsc` command banner, common service metadata, health responses, and standard build manifest use this default unless `RTPSC_RELEASE_CHANNEL` selects another valid registry channel.

An unknown `RTPSC_RELEASE_CHANNEL` fails startup or build rather than silently generating an ungoverned version.

## Operator commands

```bash
./rtpsc version --json
./rtpsc release validate
./rtpsc release list --json
./rtpsc release show beta --json
./rtpsc release manifest alpha --output build/releases/current.json
./rtpsc release promote alpha beta
./rtpsc release-build-all --clean
```

The all-channel build writes:

```text
build/releases/
├── v2.0-dev.json
├── v2.0-alpha.json
├── v2.0-beta.json
├── v2.0-rc1.json
├── v2.0-stable.json
├── v2.0-lts.json
├── v2.0-enterprise.json
├── v2.0-hotfix.json
├── catalog.json
└── SHA256SUMS
```

The regular platform build also writes:

```text
build/platform-manifest.json
build/release-manifest.json
```

## Runtime metadata

Common Node services expose the governed identity through `GET /metadata` and include the release tag and version in `GET /health`.

Example identity:

```json
{
  "company": "Ross Tax Pro Software Co",
  "product": "Ross Tax Pro Software Co Enterprise Tax Platform",
  "releaseLine": "2.0",
  "release": "v2.0-alpha",
  "version": "2.0.0-alpha.0",
  "channel": "alpha"
}
```

## Publication boundary

The all-channel builder creates local or CI evidence only. It does not create Git tags, GitHub Releases, or external deployments.

The merged manual workflow `.github/workflows/release-channel.yml` is the governed publication mechanism. With `publish=false`, it validates and uploads evidence. With `publish=true`, it may create an immutable tag and GitHub Release only after the selected protected environment permits the publication job.

A release tag does not authorize IRS, TDS, MeF, Treasury, taxpayer-record, banking, refund-release, or masterfile activity. Those capabilities remain controlled by their independent credentials, approvals, security gates, and environment protections.
