## Publication rule

Tags are immutable and are published one channel at a time through `.github/workflows/release-channel.yml`. The workflow validates the registry, installs locked dependencies, runs lint, tests, and build, rejects an existing tag, writes release evidence, and requires the channel's protected GitHub environment before publication.

Creating all eight tags against one commit is prohibited because that would classify the same artifact simultaneously as development, unstable, release candidate, stable, LTS, enterprise, and emergency-hotfix software.

## Required publication inputs

- channel
- exact branch, tag, or commit SHA
- `publish=true`
- successful validation gates
- protected environment approval
- release evidence artifact

The machine-readable index is `config/release-tag-index.json`.
